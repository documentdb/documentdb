# Engine-crasher tests: applied as pytest.mark.skip by conftest_known_failures.
# These tests are NEVER RUN. xfail is not enough for a crasher: an xfailed test
# still executes, and these crash the backend (SIGSEGV/SIGABRT in
# aggregate_cursor_first_page), restarting the whole cluster and cascading
# connection errors onto every concurrently-running test. The crasher itself
# often scores GREEN (pymongo retryable reads re-send the aggregate and the
# retry passes, or its own xfail mark absorbs the connection error), so the only
# visible symptom is unrelated tests failing "randomly" and passing on retry.
#
# Entry forms (full-prefix paths, same matching roots as ci_failing_tests.txt):
#   - exact node ID:   .../test_x.py::test_case[documentdb-param]
#   - file:            .../test_x.py            (skips every test in the file)
#   - directory:       .../some_dir/            (skips everything under it)
# Prefer the directory form for a crashing feature family: it survives suite
# pin bumps (renamed/new cases are auto-covered instead of silently running
# and crashing). Prefixes are crash-list-only by design — a prefix xfail would
# fail OPEN (mask any new failure under the directory); a prefix skip fails
# CLOSED. ci_failing/ci_flaky entries covered by a prefix here stay in their
# lists: they are shadowed while the skip exists, and removing the prefix after
# the engine fix restores the exact xfail baseline with no regeneration.
#
# Current contents: the $redact stage family (156 cases as of pinned suite
# 5a50ef4). Evidence (ADO pipeline 20085, PR 2214164 builds): every backend
# crash storm across builds 228599646 / 228536802 / 228490591 was STARTED,
# from a healthy cluster, by a $redact case — identified by matching the
# crashed backend's test database name hash (sha256(nodeid)[:8]) in
# postgres.log/gateway.log:
#   build 228599646 leg p1: test_redact_sentinel_cases[documentdb-prune_removes_embedded_document_field]  (1 crash,  sig6)
#   build 228599646 leg p2: test_redact_validation_cases[documentdb-defined_variable_current]             (12-crash storm, sig6)
#   build 228599646 leg p3: test_redact_expression_cases[documentdb-sentinel_get_field_prune]             (10-crash storm, sig11)
#   build 228536802 leg p3: test_redact_expression_cases[documentdb-sentinel_get_field_prune]             (12-crash storm, sig11)
#   build 228490591 leg p1: test_redact_output_cases[documentdb-passthrough_descend_maxkey]               (12-crash storm, sig6)
# Secondary crashes inside a storm hit unrelated error-path aggregates
# (geoNear/out/merge/indexStats/...) only during the post-restart window; legs
# with no $redact trigger (e.g. 228599646 p0/np) show ZERO crashes, so only the
# $redact family is suppressed. Crashing cases include ones that normally PASS
# (sentinels/output above), hence the directory form rather than per-case IDs.
#
# Remove the entry when the engine $redact crash is fixed; the long-term home
# for this knowledge is the suite's own engine_xcrash marker (upstream
# documentdb/functional-tests), which the dedicated crash job can still opt
# into via --run-crash-tests.
